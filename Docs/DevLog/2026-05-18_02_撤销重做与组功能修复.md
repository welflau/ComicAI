# 2026-05-18_02 撤销重做 + 组功能系列修复

## 撤销/重做（Ctrl+Z / Ctrl+Y）

### 实现

`projectStore` 新增 `_undoStack` / `_redoStack`（各限 50 步）：

```ts
pushHistory()   // 手动快照（拖拽开始时调用）
undo()          // 恢复上一步，当前状态推入 redoStack
redo()          // 恢复下一步，当前状态推入 undoStack
```

**自动快照时机（内建在 action 里）：**
- `addNode` / `addEdge` / `deleteNode` / `groupNodes` — action 内部自动 push
- `onNodeDragStart` — 拖拽开始时 push（拖拽结束触发 saveWorkflow，位置已更新）
- `onNodesDelete` / `onEdgesDelete` — 批量删除前 push

**键盘绑定（WorkflowCanvas）：**
- `Ctrl+Z` → undo
- `Ctrl+Y` / `Ctrl+Shift+Z` → redo
- 文本输入框（INPUT/TEXTAREA）内不响应

## 组功能系列修复

### fix: 退出组后根层节点不丢失

**根因**：`saveWorkflow(ns, es)` 将 ReactFlow 当前 nodes（只含组内节点）调用
`updateWorkflow` 直接覆盖整个 store，根层节点被清空。

**修复**：`saveWorkflow` 按 `currentGroupId` 分层：
- 保留其他层级的 nodes/edges 不动
- 只替换属于当前层的节点（带最新 position）和连线

### fix: 进组后画布空白

**根因**：进组后 `currentGroupId` 变化，`storeNodes` 正确过滤出组内节点，但
ReactFlow 的 `fitView` 视口未跟随，节点跑到屏幕外。

**修复**：WorkflowCanvas 用 `useRef` 跟踪 `prevGroupId`，变化时延迟 80ms 调
`fitView`，且只对内容节点（排除端口节点）做 fitView，避免端口极端位置导致缩很小。

### fix: 打组后组内为空

**根因**：先 `addNode` × N，再调 `groupNodes` 两步走存在时序问题，`groupNodes`
拿到旧 state 导致 `groupId` 未写入章节节点。

**修复**：预先生成 `groupId`，`addNode` 时直接携带，一步到位。

### fix: loadProject 重置组导航

`loadProject` 三条分支均未重置 `currentGroupId` / `groupNavStack`，同 session
内切换项目后旧组 ID 残留，`storeNodes` 过滤不出任何节点，画布无法交互。

三处 `set()` 均补充：
```ts
currentGroupId: null, groupNavStack: [],
_undoStack: [], _redoStack: [],
```

## 节点风格规范修复

### ChapterSplitNode 风格统一

- 外层改为统一 `border: 1.5px solid #2e2e2e` + `overflow: hidden`，selected 时紫色高亮
- 「开始章节分解」从实心紫改为轮廓风格（透明背景 + 紫色描边）

### Handle 可见性规范

**规范**：所有节点的连接按钮（+ 号 / handle）只在 **hover 或选中时** 显示。

修复的节点：`GroupNode` / `LoopNode` / `ChapterSplitNode`
- 新增 `hovered` state，外层 div 加 `onMouseEnter/onMouseLeave`
- `handlesVisible = !dragging && (selected || hovered)`

### GroupPortNode 优化

- 输入（蓝）/ 输出（橙）醒目颜色，半透明背景 + 发光边框
- 缩放不变：`scale(1/zoom)` 补偿，视觉固定 88×36px
- Handle 移入 counter-scaled 内层 div，连接点与视觉边缘对齐
