## Phase 1 — P0 基础体验补全

### 1.1 图片工具栏 API 接入

**背景**：当前 `ImageEditToolbar` 的「多角度」「打光」「九宫格」「HD 高清」「宫格切分」按钮全部无效，用户体验极差。本次优先补全三个高频能力：HD 超分、抠图（Remove BG）、扩图（Outpaint）。

**实现方案**

| 按钮 | API 端点 | 参考 |
|---|---|---|
| 高清（HD Upscale） | `POST /lightai/upscale` — 传入图片 URL，返回高清 URL | Tapnow 使用即梦超分接口 |
| 抠图（Remove BG） | `POST /lightai/removebg` — 返回透明 PNG | 调用 LightAI 统一通道 |
| 扩图（Outpaint） | `POST /lightai/outpaint` — 传入方向/比例，返回扩展图 | 调用 LightAI 统一通道 |

**涉及文件**

- `frontend/src/components/nodes/ImageNode.tsx`
  - `TOOLBAR_GROUPS` 中的 `hd`、`removebg`、`outpaint` 按钮绑定 `onClick` 处理函数
  - 新增 `handleUpscale()`、`handleRemoveBg()`、`handleOutpaint()` 三个函数
  - 处理中显示 loading 状态（按钮 spinner），完成后更新节点 `imageUrl`
- `frontend/src/api/index.ts`
  - 新增 `imageEditApi.upscale(url)`、`imageEditApi.removebg(url)`、`imageEditApi.outpaint(url, direction)`
- `backend/app/api/v1/endpoints/image_edit.py`（新建）
  - `POST /image-edit/upscale`
  - `POST /image-edit/removebg`
  - `POST /image-edit/outpaint`
  - 统一调用 LightAI 对应接口，返回新图片 URL

**验收标准**
- 图片节点生成图片后，点击「高清」按钮 → loading → 节点图片替换为高清版本
- 点击「抠图」→ 返回透明背景 PNG，节点图片更新
- 点击「扩图」→ 弹出方向选择（左/右/上/下/等比），确认后返回扩展图

### 1.2 多 API Key 支持 + 黑名单轮换

**背景**：当前只支持单个 API Key（settings 中一个 LightAI key）。批量生产场景下，单 Key 积分耗尽后整个流程停摆。Tapnow Studio 有完整的多 Key 黑名单机制可参考。

**实现方案**

**后端 Key 管理（推荐方案：后端轮询，前端无感知）**

1. **数据模型**：`settings` 表新增 `api_keys` 字段（JSON 数组），每条 Key 含：
   ```json
   { "key": "sk-xxx", "disabled": false, "disabled_until": null, "disable_reason": "" }
   ```

2. **Key 选择器** `backend/app/services/key_manager.py`（新建）：
   - `get_available_key()` — 轮询返回当前可用 Key（跳过黑名单中的）
   - `blacklist_key(key, reason, duration_minutes)` — 拉黑指定 Key
   - 定时任务（APScheduler）每天 0 点重置所有黑名单
   - 错误码映射：
     - `1006`（积分耗尽）→ 永久拉黑（当日）
     - `401/402/403` → 临时拉黑 60 分钟

3. **API 调用层改造** `backend/app/services/lightai.py`（或 `api_client.py`）：
   - 每次调用前通过 `key_manager.get_available_key()` 取 Key
   - 捕获特定错误码 → `blacklist_key()` → 自动重试（最多 3 次换 Key）

**前端 Key 管理面板**（设置页面）
- 将单行 Key 输入改为可增删的列表
- 每行显示 Key（脱敏）+ 状态（可用 / 拉黑中 + 剩余时间）
- 「清空黑名单」按钮

**涉及文件**
- `backend/app/services/key_manager.py`（新建）
- `backend/app/services/lightai.py` — 接入 key_manager
- `frontend/src/components/settings/ApiKeyManager.tsx`（新建）
- `frontend/src/api/index.ts` — 新增 key 管理 API

**验收标准**
- 配置 3 个 Key，其中 1 个积分耗尽 → 自动切换到下一个 Key，生成继续执行
- 黑名单面板显示被拉黑的 Key 和原因
- 「清空黑名单」后所有 Key 恢复可用

## Phase 2 — P1 核心创作能力

### 2.1 局部重绘 MaskEditor

**背景**：图片编辑的核心高频功能。Tapnow Studio 有完整的 ~300 行 `MaskEditor` Canvas 组件可作为参考（`F:/A_Works/Tapnow-Studio-PP/src/App.jsx` 第 1294 行起）。

**实现方案**

**组件结构**
```
MaskEditor（Modal 全屏覆盖层）
  ├── Canvas 层 1：原图显示
  ├── Canvas 层 2：蒙版绘制（半透明红色笔刷）
  ├── 工具栏：笔刷大小滑块、橡皮擦切换、清空、确认
  └── 提示词输入框 + 发送按钮
```

**技术要点**（参考 Tapnow 实现）
- 笔刷绘制：`mousedown/mousemove` 在蒙版 Canvas 上 `fillRect`（半透明红色）
- 橡皮擦：`destination-out` 混合模式擦除蒙版
- 导出：`canvas.toDataURL('image/png')` 获取蒙版图（白色为重绘区域，黑色为保留区域）
- API 调用：将原图 + 蒙版图 + 提示词传给 LightAI inpaint 接口

**流程**
1. 图片节点工具栏新增「局部重绘」按钮（替换或扩展现有「图片编辑器」按钮）
2. 点击 → 打开 `MaskEditor` Modal，传入当前图片 URL
3. 用户在图片上涂抹要重绘的区域
4. 输入描述 → 点击生成 → 调用后端 inpaint API
5. 返回结果更新节点图片（或作为新的图片节点）

**涉及文件**
- `frontend/src/components/editor/MaskEditor.tsx`（新建）
- `frontend/src/components/nodes/ImageNode.tsx` — 工具栏新增入口
- `frontend/src/api/index.ts` — 新增 `imageEditApi.inpaint(originalUrl, maskBase64, prompt)`
- `backend/app/api/v1/endpoints/image_edit.py` — 新增 `POST /image-edit/inpaint`

**验收标准**
- 在图片上涂抹区域后输入「一只猫」→ 涂抹区域替换为猫
- 笔刷大小可调，橡皮擦可撤销
- 蒙版可清空重新绘制

### 2.3 小说输入节点 + 角色/场景自动提取

**背景**：漫剧创作的上游工作流 — 从小说/剧本文本自动提取角色描述和场景描述，直接送入生图节点。Tapnow Studio 有完整的 `novel-input` → `extract-characters-scenes` → `character-description` / `scene-description` 链路。

**实现方案**

**新节点类型**

1. **小说输入节点** `NovelInputNode`
   - 支持粘贴最多 10,000 字的文本
   - 显示字数统计
   - 输出：文本内容（连线到提取节点）

2. **角色/场景提取节点** `ExtractNode`
   - 接收上游文本（小说/剧本）
   - 调用 LLM（Claude / GPT）自动提取：
     - 角色列表（姓名、外貌、服装、性格特征）
     - 场景列表（地点、环境、时代背景、氛围）
   - 提取结果以可编辑卡片形式展示
   - 每个角色/场景卡片可连线到 ImageNode（作为生图提示词）

**数据流**
```
NovelInputNode → ExtractNode → [CharacterCard, SceneCard] → ImageNode（提示词自动填充）
```

**涉及文件**
- `frontend/src/components/nodes/NovelInputNode.tsx`（新建）
- `frontend/src/components/nodes/ExtractNode.tsx`（新建）
- `frontend/src/utils/nodeTypes.ts` — 注册新节点类型
- `frontend/src/components/NodePicker.tsx` — 节点选择菜单新增入口
- `backend/app/api/v1/endpoints/extract.py`（新建）— `POST /extract/characters-scenes`

**验收标准**
- 粘贴一段小说文本 → 提取节点自动列出角色和场景
- 点击某个角色 → 自动连线到 ImageNode 并填充角色描述提示词
- 可手动编辑提取结果

### 3.2 视频分析节点（智能抽帧）

**背景**：Tapnow Studio 的 `video-analyze` 节点支持：① 基于像素差值的场景检测算法自动识别镜头切换；② 提取关键帧后送 Gemini 分析运镜/口播；③ 反推 Midjourney/即梦提示词。这对于「参考视频 → 分镜脚本」场景非常有价值。

**实现方案**

**前端新节点** `VideoAnalyzeNode`
- 接收上游 VideoNode 的视频 URL
- 触发「分析」后调用后端接口
- 展示：关键帧缩略图列表 + 每帧的运镜分析文本

**后端分析服务** `backend/app/services/video_analyzer.py`（新建）
- **场景检测**（参考 Tapnow `detectScenesAndCapture` 算法）：
  - 使用 `ffmpeg` 按固定帧率提取帧（如每秒 2 帧）
  - 计算相邻帧的像素差值，超过阈值则判断为场景切换
  - 取每个场景的第一帧作为关键帧
- **AI 分析**：将关键帧列表送入 LLM（Claude Vision / Gemini）分析：
  - 运镜手法（推/拉/环绕/固定等）
  - 主体动态描述
  - 光影氛围
  - 反推生图提示词
- 返回：`[{ frame_url, timestamp, camera_move, description, prompt }]`

**涉及文件**
- `frontend/src/components/nodes/VideoAnalyzeNode.tsx`（新建）
- `frontend/src/utils/nodeTypes.ts` — 注册节点类型
- `backend/app/services/video_analyzer.py`（新建）
- `backend/app/api/v1/endpoints/video_analyze.py`（新建）
- 依赖：服务器需安装 `ffmpeg`

**验收标准**
- VideoAnalyzeNode 连接视频节点 → 点击分析 → 返回 3-5 个关键帧缩略图
- 每帧下方显示运镜分析文本和反推提示词
- 可将某帧提示词一键复制到图片/视频节点

### 3.3 工作流 ZIP 导出/导入

**背景**：用户有换机迁移、备份、分享工作流的需求。Tapnow Studio 使用 JSZip 将 `project.json` + `assets/` 打包为 `.zip` 文件导出。ComicFlow 目前无任何导出功能。

**实现方案**

**导出**
1. 前端收集：当前画布的 nodes + edges JSON
2. 收集所有 `/uploads/...` 资源 URL → 通过后端 `/workflow/export` 打包
3. 后端：将 workflow JSON + assets 文件复制到临时目录 → `zipfile` 打包 → 返回 .zip 文件流
4. 前端：浏览器自动下载 `{项目名}-{日期}.comicflow.zip`

**导入**
1. 用户上传 `.comicflow.zip`
2. 后端解压 → 解析 `workflow.json` → 迁移 assets 到 `uploads/` → 创建新项目记录
3. 前端刷新项目列表，新项目出现

**涉及文件**
- `backend/app/api/v1/endpoints/workflow_io.py`（新建）— `GET /workflow/export/{project_id}`、`POST /workflow/import`
- `frontend/src/components/toolbar/TopBar.tsx`（或项目页面） — 新增「导出工作流」「导入工作流」按钮

**验收标准**
- 点击「导出」→ 下载 `.zip` 文件，解压后有 `workflow.json` + `assets/` 目录
- 将 `.zip` 导入到另一账号/环境 → 项目完整还原，图片正常显示

### 4.2 性能分级渲染

**背景**：画布节点超过 20 个时 FPS 明显下降。Tapnow Studio 使用三档缩略图（80px/150px/原图）+ 视口外媒体卸载策略。

**实现方案**
- **缩放等级判断**：ReactFlow `useStore` 获取当前 zoom 值
  - zoom < 0.3：全部节点显示 80px 缩略图
  - 0.3–0.7：显示 150px 缩略图
  - zoom > 0.7：显示原图
- **视口外卸载**：使用 IntersectionObserver 检测节点是否在视口内，视口外的媒体元素替换为占位符（灰色矩形）
- **图片懒加载**：ImageNode 的 `<img>` 改为 `loading="lazy"` + 骨架屏

**涉及文件**
- `frontend/src/components/nodes/ImageNode.tsx` — 接入 zoom 判断
- `frontend/src/components/nodes/VideoNode.tsx` — 视口外停止播放 / 卸载
- `frontend/src/hooks/useNodeVisibility.ts`（新建）— IntersectionObserver 封装

## 依赖与注意事项

| 事项 | 说明 |
|---|---|
| LightAI API 文档 | 接入 HD/抠图/扩图/inpaint/视频延长前，需确认 LightAI 对应端点和参数格式 |
| ffmpeg | 视频分析节点需要服务器安装 `ffmpeg`（`apt install ffmpeg` 或 Docker 镜像预装） |
| 图片存储路径 | MaskEditor 的蒙版图建议临时存内存（base64），不持久化到 `uploads/`，避免占用存储 |
| Veo 3 原生音频 | 通过即梦代理通道时，需确认是否支持 Veo 3 的音频输出选项 |
| 角色库与 Tapnow 的差异 | Tapnow 用 localStorage；ComicFlow 存后端（更安全），但需要额外 API 接口 |
