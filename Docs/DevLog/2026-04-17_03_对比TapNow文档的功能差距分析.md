# 2026-04-17 对比 TapNow 文档的功能差距分析

## 背景

参考 [TapNow 文档](https://docs.tapnow.ai/zh/docs) 的功能结构，对照 ComicFlow 当前实现，梳理已有能力、待补齐功能及产品方向差异。

TapNow 是同类 AI 创作平台（无限画布 + 节点工作流），主打图片 / 视频生成，面向内容创作者。

## 二、核心差距详述

### 1. 图片编辑能力（优先级高）

TapNow 图片节点工具栏的「局部重绘」「扩图」「抠图」是用户高频需求，ComicFlow 目前：
- 工具栏按钮 UI 已有（多角度/打光/九宫格/HD），但**全部未接后端 API**
- 缺少「局部重绘」（inpaint）：选区 + 蒙版 → AI 填充指定内容
- 缺少「扩图」（outpaint）：向外延伸画面边界
- 缺少「抠图」（remove background）：AI 去除背景，导出透明 PNG

**建议方向：** 接入 LightAI 的 inpaint / outpaint / removebg 接口，工具栏改为真实可用状态。

---

### 2. Veo 3 模型接入（优先级中）

TapNow 专门有「Veo3 提示词技巧」文档章节，说明 Veo 3 是其主推模型之一。ComicFlow 目前只有 Seedance 1.5 + Kling 3.0，缺少 Google Veo 3。

- Veo 3 特点：原生音频生成、高质量物理模拟
- 接入方式：通过 LightAI 统一接口扩展（与 Seedance / Kling 同路）
- VideoNode 的 `VideoModel` 类型 + `MODEL_OPTIONS` 只需新增一项

---

### 3. 视频延长功能（优先级中）

TapNow 支持对已有视频「一键延长」（续写下一段），ComicFlow 目前生成视频后无法继续延伸。

**建议：** 视频节点工具栏加「延长」按钮，调用 LightAI 的 video extend 接口，将当前视频末帧作为新视频首帧。

---

### 4. 角色库（优先级中）

左侧工具栏「角色库」入口已存在（UI 占位），但功能未实现。TapNow 的角色库允许：
- 保存角色参考图（外貌、服装、风格）
- 创建节点时直接引用角色，确保角色一致性

**建议：** 后端新增 `characters` 表，前端实现角色 CRUD + 节点中的「引用角色」能力。

---

### 5. 资产库（优先级低）

TapNow 强调「素材永久沉淀、多次复用」——跨项目资产复用。ComicFlow 目前：
- 图片/视频存在项目对应的 `uploads/` 目录中
- 无跨项目的全局资产管理 UI

---

### 6. 图片工具栏功能补全（优先级高）

当前 `ImageEditToolbar` 现状：

| 按钮 | 当前状态 |
|---|---|
| 多角度 | UI 存在，无功能 |
| 打光 | UI 存在，无功能 |
| 九宫格 | UI 存在，无功能 |
| HD 高清 | UI 存在，下载功能有，高清放大未接 API |
| 宫格切分 | UI 存在，无功能 |

对比 TapNow 期望工具栏：全屏、下载、**抠图（接 API）**、**高清（接 API）**、**扩图（接 API）**、图片编辑器

---

## 三、已有优势（ComicFlow 独有）

| 能力 | 说明 |
|---|---|
| 漫剧脚本专项节点 | ScriptGenNode 支持剧本生成分镜脚本、角色生成分镜脚本，TapNow 无 |
| 分镜 + 时间轴视图 | StoryboardView + TimelineView，专为漫剧制作场景设计 |
| 脚本 → 分镜 → 图片 → 视频 完整流水线 | ComicFlow 的核心差异化，TapNow 偏通用创作 |

---

## 四、建议优先级排序

| 优先级 | 功能 | 原因 |
|---|---|---|
| P0 | 图片工具栏 API 接入（HD、抠图、扩图） | 工具栏已有 UI 但不可用，用户体验差 |
| P1 | 局部重绘（inpaint） | 图片编辑核心功能，TapNow 主打 |
| P1 | 视频延长 | 短剧制作续集镜头的刚需 |
| P2 | Veo 3 模型 | 竞品主推，用户有预期 |
| P2 | 角色库 | 漫剧场景下角色一致性是痛点 |
| P3 | 资产库 | 多项目用户才有感知 |
| P3 | Agent 自动化 | 需要较大架构投入 |
