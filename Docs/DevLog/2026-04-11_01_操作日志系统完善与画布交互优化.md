# 操作日志系统完善与画布交互优化

**日期：** 2026-04-11

---

## 背景

Log 面板的"操作"Tab 之前没有实质内容，或被大量无意义的"工作流已保存"条目淹没（每次节点拖动、删除、连线都会触发 `updateWorkflow` 写日志）。本次迭代目标：把"用户做了什么"与"系统在后台保存了什么"彻底分离，让操作 Log 只记录真正有意义的用户行为。

---

## 核心设计原则

**噪音来源：** `updateWorkflow` 是一个持久化副作用，被 drag stop / delete / connect 等多个事件链式调用，每次都 log 导致面板被刷屏。

**修复策略：** 持久化操作静默处理（仅在 error 时记录），用户手势在其源头处记录。

```
❌ 之前：用户拖动节点 → onNodeDragStop → saveWorkflow → updateWorkflow → addLog("工作流已保存")
✅ 之后：用户拖动节点 → onNodeDragStop → addLog("移动节点: xxx") → saveWorkflow（静默）
```

---

## 变更详情

### 1. `projectStore.ts` — 移除噪音日志

- **`updateWorkflow`**：移除所有成功路径的 `addLog`（本地 IndexedDB 和远端 API 两条路径均清除）。仅保留 `catch` 块里的 error 级别日志。
- **`updateNode`**：移除 `addLog`（每次按键都调用，极度嘈杂）。

### 2. `WorkflowCanvas.tsx` — 在手势源头记录日志

| 回调 | 记录内容 |
|------|----------|
| `onNodeDragStop` | `移动节点: <label>`，含落点坐标 |
| `onNodesDelete` | `删除节点: <label>`，含类型和 ID（键盘 Delete 触发路径） |
| `onEdgesDelete` | `删除连接`，含 source → target |
| `onConnect` | `连接已创建`，含 source → target |
| `handleDelete`（右键菜单） | `删除节点: <label>`，含类型和 ID |
| `handleDuplicate` | `节点已复制: <label>`，含原节点 ID 和类型 |

**防误触优化：** 点击选中节点时 `onNodeDragStop` 也会触发，但位移为 0。新增 `onNodeDragStart` 记录起始坐标，`onNodeDragStop` 时比较位移，若 `dx < 1 && dy < 1` 则跳过 log 和保存，不再产生虚假的"移动节点"条目。

```typescript
const onNodeDragStart = useCallback((_: unknown, node: Node) => {
  dragStartPos.current = { x: node.position.x, y: node.position.y }
}, [])

const onNodeDragStop = useCallback((_: unknown, node: Node) => {
  const start = dragStartPos.current
  dragStartPos.current = null
  const dx = start ? Math.abs(node.position.x - start.x) : 0
  const dy = start ? Math.abs(node.position.y - start.y) : 0
  if (dx < 1 && dy < 1) return  // 仅选中，无位移
  addLog({ ... })
  saveWorkflow(nodes, edges)
}, [nodes, edges, saveWorkflow])
```

### 3. `TemplatePicker.tsx` — 模板应用日志

在 `pick()` 中调用 `updateWorkflow` 前补充日志：

```typescript
addLog({
  level: 'info', category: 'operation',
  message: `应用模板: ${tpl.name}`,
  detail: `模板ID: ${tpl.id} | 节点数: ${tpl.nodes.length} | 连接数: ${tpl.edges.length}`,
})
```

### 4. `NodeAddMenu.tsx` — 通过节点把手添加节点的日志

在 `handleSelect` 完成 `addNode` + `addEdge` 后记录：

```typescript
addLog({
  level: 'info', category: 'operation',
  message: `添加节点: ${item.targetLabel}`,
  detail: `类型: ${item.targetType} | 从节点 ${sourceNodeId} 出发 (方向: ${direction === 'right' ? '右' : '左'})`,
})
```

### 5. `LeftPanel.tsx` — 从节点库拖拽的日志

在 `handleDragStart` 中记录：

```typescript
addLog({
  level: 'info', category: 'operation',
  message: `拖拽节点: ${node.label}`,
  detail: `类型: ${node.type} | 分类: ${node.category}`,
})
```

### 6. `ImageNode.tsx` — 图片生成与上传日志

| 时机 | 记录内容 |
|------|----------|
| 开始生成 | `开始生成图片: <label>`，含节点 ID 和 Prompt 预览 |
| 生成完成 | `图片生成完成: <label> (Xs)`，含耗时 |
| 生成失败 | `图片生成失败: <label>`，含错误信息（error 级别） |
| 文件上传 | `上传图片: <label>`，含文件名和大小 |

### 7. `ScriptNode.tsx` — 剧本操作日志

| 操作 | 记录内容 |
|------|----------|
| 进入编写模式 | `剧本节点: 进入编写模式` |
| 添加分镜节点 | `添加分镜脚本节点` |
| 开始 AI 生成 | `脚本生成: 开始`（operation 类别，与已有 ai 类别日志并存） |

## 修复的问题

- **选中节点误触发"移动节点"日志**：点击选中时 `onNodeDragStop` 也会触发，通过比较 drag start/stop 位移（< 1px 则跳过）解决。同时避免了无实际位移时的多余 `saveWorkflow` 调用。
