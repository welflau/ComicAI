# AI 结构化输出与画布操作（Phase 2: Function Calling）

Date: 2026-04-18  
Status: 已完成  
Priority: P1

---

## 一、背景

前一阶段（`2026-04-18_03`）使用硬编码正则匹配识别用户意图（ADD_NODE、ADD_WORKFLOW 等），被用户指出"写死的回答，不是 AI 自己回答"。

本次实现 **Phase 2**：AI 自身理解意图，通过结构化 JSON 输出决定是否执行画布操作，而不是前端 regex 硬判断。

---

## 二、设计方案

### 核心思路

后端 system prompt 告知 AI：**始终以 JSON 格式回复**，格式为：

```json
{
  "reply": "给用户看的自然语言回复",
  "actions": [ /* 零个或多个 canvas action */ ]
}
```

AI 根据用户意图自行决定是否填写 `actions`，无需前端写死规则。

### 支持的 Action 类型

| type | 说明 |
|------|------|
| `ADD_NODE` | 添加单个节点，含 `nodeType`、`nodeLabel` |
| `ADD_WORKFLOW` | 多节点工作流，含 `nodes[]`、`edges[]` |
| `DELETE_SELECTED` | 删除当前选中节点 |
| `CLEAR_CANVAS` | 清空全部节点 |

   ```python
   # 尝试 JSON 解析，提取 reply + actions
   clean = reply.strip()
   if clean.startswith("```"):
       # 去掉 markdown code fence
       clean = re.sub(r'^```[a-zA-Z]*\n?', '', clean)
       clean = re.sub(r'\n?```$', '', clean.strip()).strip()
   parsed = json.loads(clean)
   reply = parsed.get("reply", reply)
   actions = parsed.get("actions", [])
   # 若解析失败，fallback：原始文本作为 reply，actions=[]
   ```

## 四、架构说明

### 硬编码 Intent 保留

`matchIntent()` 正则快速路径**仍然保留**，作为两层防御：

1. **层 1（前端，快）**：`matchIntent()` 正则 → 立即响应，无需网络请求
2. **层 2（后端，智能）**：AI 结构化输出 → 理解模糊/复杂请求

这样简单命令（"添加图片节点"）响应更快，复杂请求（"我想做一个带配音的短视频，帮我搭建"）由 AI 推理出完整工作流。

### Fallback 健壮性

若 AI 未返回合法 JSON（如旧模型、网络截断），`json.loads` 抛出异常，后端 fallback 为：
- `reply` = 原始文本
- `actions` = `[]`

前端也对 `res.actions || []` 做防御，即使后端未升级也能正常工作。
