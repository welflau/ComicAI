# 2026-04-20_05 img2prompt 默认图片修复

## 背景

上一轮（`_04`）修复了 img2prompt 功能的 JSON 输出问题和上游图片检测问题，但遗留一个缺陷：
img2prompt 快捷操作创建的 ImageNode 使用 `DEFAULT_IMAGE_URL = 'default://placeholder'` 作为初始图片，
该特殊 URL 在 `resolveImageToDataUrl()` 中被明确排除（返回 `null`），导致 AI 无法看到任何图片内容。

---

## 问题分析

| 路径 | 行为 |
|------|------|
| `default://placeholder` | `resolveImageToDataUrl` 直接返回 `null`，AI 收不到图片 |
| `/assets/placeholder-image-xxx.webp` | `resolveImageToDataUrl` 通过 `fetch` + base64 转换，AI 能收到真实图片 |

`imageStore.ts` 已将 `placeholder-image.webp` 以 Vite 资产方式导入为 `placeholderImageUrl`，
该变量在运行时会被解析为 `/assets/placeholder-image-xxxxxxxx.webp` 格式的哈希路径。

---

## 修复方案

在 `ScriptNode.tsx` 中：

1. 新增 `import placeholderImageUrl from '@/assets/placeholder-image.webp'`
2. `handleQuickAction('img2prompt')` 创建 ImageNode 时将 `imageUrl` 从 `DEFAULT_IMAGE_URL` 改为 `placeholderImageUrl`

```typescript
// ScriptNode.tsx — handleQuickAction('img2prompt')
import placeholderImageUrl from '@/assets/placeholder-image.webp'

// 创建 ImageNode 时：
imageUrl: placeholderImageUrl,   // 原：DEFAULT_IMAGE_URL
```

---

## 效果

- ImageNode 初始化时携带真实的 webp 资产路径（`/assets/placeholder-image-xxx.webp`）
- `sourceImageRef` 能正确识别该路径（不以 `default://` 开头，通过过滤条件）
- `resolveImageToDataUrl` 对 `/` 路径的 fetch + base64 处理链路正常工作
- AI 能实际看到默认图片内容，img2prompt 功能完整可用
- `isImg2PromptMode` 警告 guard（`!imageRefSnapshot`）不再误触发
