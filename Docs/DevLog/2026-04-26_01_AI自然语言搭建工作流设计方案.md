# 2026-04-26_01 AI 自然语言搭建工作流设计方案

## 背景

用户通过自然语言描述创作需求，AI 自动在画布上搭建完整生成流水线（节点 + 连线 + 初始内容），无需手动添加节点。

---

## 问题拆解

### 两个独立层

| 层 | 职责 | 当前状态 |
|---|---|---|
| **图构建层** | AI 理解自然语言 → 生成节点图 | ✅ 基础已有 |
| **图执行层** | 节点自动级联运行（A 完成触发 B） | ❌ 尚未实现 |

本文聚焦**图构建层**（自然语言 → 搭建工作流），图执行层（WorkflowRunner）为后续独立任务。

---

## 现状：已有什么

基础管道已经存在，链路已通：

```
用户自然语言
    ↓
ai_assistant.py — 调用 Claude/GPT，返回结构化 JSON
    { "reply": "...", "actions": [{ "type": "ADD_WORKFLOW", "nodes": [...], "edges": [...] }] }
    ↓
RightPanel.tsx — 解析 actions，调用 addNode + addEdge
    ↓
画布上出现节点和连线
```

关键文件：

| 文件 | 作用 |
|---|---|
| `backend/app/api/v1/endpoints/ai_assistant.py` | 系统提示词 + AI 调用 + JSON 解析 |
| `frontend/src/components/panels/RightPanel.tsx` L719 | `ADD_WORKFLOW` 执行：批量创建节点并连线 |

## 缺口：做漫画流水线还差什么

### 1. 节点创建时没有初始数据（最关键）

现在 `ADD_WORKFLOW` 只传 `nodeType + nodeLabel`，节点创建出来是空壳。

```json
// 现在
{ "nodeType": "libtv_image", "nodeLabel": "图片" }

// 需要扩展
{ "nodeType": "libtv_image", "nodeLabel": "分镜1",
  "nodeConfig": { "imagePrompt": "女侠，雪山背景，对决姿势，近景" } }
```

### 2. 不支持 1 → N 扇出

漫画流水线是「1 个 ScriptGenNode → N 个 ImageNode」，但当前 ADD_WORKFLOW 只支持线性链。需要允许同一 fromIdx 出现在多条 edge 里。

### 3. System prompt 缺漫画工作流案例

AI 目前不知道「漫画生成」= `libtv_script` → `libtv_script_gen` → N×`libtv_image`，需要在 `PLATFORM_SYSTEM_PROMPT` 里补充该场景的 few-shot 示例。

---

## 最小改动方案（三步）

### Step 1 — 扩展后端 prompt（~10 行）

在 `ai_assistant.py` 的 `ADD_WORKFLOW` schema 定义里增加 `nodeConfig` 字段，并补充漫画工作流示例：

```json
{
  "type": "ADD_WORKFLOW",
  "nodes": [
    { "nodeType": "libtv_script",     "nodeLabel": "剧本",
      "nodeConfig": { "content": "一个女侠在雪山上决斗..." } },
    { "nodeType": "libtv_script_gen", "nodeLabel": "分镜脚本" },
    { "nodeType": "libtv_image",      "nodeLabel": "分镜1",
      "nodeConfig": { "imagePrompt": "女侠，雪山，对决，近景" } },
    { "nodeType": "libtv_image",      "nodeLabel": "分镜2",
      "nodeConfig": { "imagePrompt": "刀光剑影，特写" } }
  ],
  "edges": [
    { "fromIdx": 0, "toIdx": 1 },
    { "fromIdx": 1, "toIdx": 2 },
    { "fromIdx": 1, "toIdx": 3 }
  ]
}
```

### Step 2 — 前端执行时注入 nodeConfig（~5 行）

`RightPanel.tsx` L727 的 `workflowNodes.forEach` 里，把 `n.config` 传给 `addNode`：

```ts
addNode({
  id: newId,
  type: n.type,
  label: n.label,
  position: { x: baseX + i * 260, y: baseY },
  config: {},
  ...n.config,   // ← 新增：注入 imagePrompt / content 等
})
```

### Step 3 — 支持扇出（~2 行）

`workflowEdges` 里 `fromIdx` 重复出现时直接循环处理即可，不需要额外逻辑（当前代码已用 `forEach` 遍历，不会报错，只需验证）。

## 关于「收集截图是否有帮助」

**结论：截图对 LLM 生成结构化工作流帮助有限，但有两个有效用途：**

| 用途 | 有效性 | 说明 |
|---|---|---|
| 截图作 few-shot 视觉示例 | ❌ 低 | AI 输出的是 JSON，不是像素坐标，视觉布局信息用处不大 |
| 截图 → 文本案例 → 写入 prompt | ✅ 高 | 从截图提炼出「场景+节点结构+连线模式」的文本描述，作为 few-shot 示例 |
| 截图 → Vision 反解析 → 重建工作流 | ✅ 有趣功能 | 用户截别人的工作流图，AI 看图识别节点类型和连线，自动在画布重建（接口已有 `image_data_url` 支持）|

**实际建议**：收集成功案例的 JSON 导出（节点+连线+配置），整理成 3~5 个典型模板写进 system prompt，比截图更直接有效。

---

## 典型目标效果

用户输入：`帮我生成一个 5 镜头的古风爱情漫画工作流`

AI 输出并执行：
- 1 个 ScriptNode（预填故事梗概）
- 1 个 ScriptGenNode（分镜脚本生成器）
- 5 个 ImageNode（各自预填对应镜头的 imagePrompt）
- 连线：Script → ScriptGen → Image×5

用户只需点「生成」即可逐节点执行。

3. 节点组件响应 `injectedInputs` 变化自动 run

这是独立的下一阶段任务。
