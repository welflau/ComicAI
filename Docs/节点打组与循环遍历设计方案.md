# 节点打组与循环遍历设计方案

## 背景

画布节点过多时（如小说 28 个章节节点）难以管理。需要：
1. **打组**：将多个节点收纳进一个「组节点」，画布只显示一个节点
2. **组内层级**：双击组节点进入组内画布，查看/编辑内部节点
3. **连线简化**：外部只连组节点，不需要连接组内每个节点
4. **自动排版**：组内节点可按规律自动布局
5. **循环遍历**：循环节点连接组节点，逐一遍历组内指定类型的节点

---

## 功能一：组节点（`libtv_group`）

### 1.1 外观（收起状态）

```
┌─────────────────────────────────┐
│ 📦 第一幕章节组                  │  ← 标题
│    28 个节点  文字×28            │  ← 内容摘要
│                      [展开] [⚙] │
└─────────────────────────────────┘
         ○ ←──── 外部连线（输入）
         ○ ────→ 外部连线（输出）
```

### 1.2 进入组内（展开状态）

- 双击组节点 → 画布**导航进入**组内层级，顶部显示面包屑 `画布 / 第一幕章节组`
- 组内是完整的 ReactFlow 画布，支持所有节点操作
- 点面包屑返回上层画布
- 组内节点的连线不影响外部

### 1.3 组的 I/O 映射

- 组节点左侧 Handle = 组内「入口节点」的输入（可设置哪个内部节点接收外部数据）
- 组节点右侧 Handle = 组内「出口节点」的输出（可设置哪个内部节点对外输出）
- 简单实现：先不做映射，组节点仅作为「容器」，循环节点直接读取组内节点列表

### 1.4 创建方式

1. **框选 → 打组**：框选多个节点后，右键菜单 → 「打组」→ 自动创建组节点并移入
2. **新建空组**：AddNodePanel 添加组节点，再手动拖入

### 1.5 自动排版

组内节点太多时，点「自动排版」按钮，按以下规则重排：
- `grid`：等间距网格（适合同类型大量节点）
- `tree`：从左到右拓扑排列（适合有连线的工作流）
- 默认间距：横向 320px，纵向 260px

## 功能二：循环遍历节点（`libtv_loop`）

### 2.1 用途

连接一个组节点，逐一遍历组内指定类型的节点，将每个节点的内容依次推送给下游。

### 2.2 外观

```
┌──────────────────────────────────┐
│ 🔁 循环遍历                        │
│  来源：[第一幕章节组 ▼]            │
│  类型：[文字节点     ▼]            │
│  进度：3 / 28                     │
│  ◀ 上一个   [▶ 推送当前]  下一个 ▶ │
│                                  │
│  当前：第三章 命运的错误           │
│  字数：1,247                     │
└──────────────────────────────────┘
      ○ ────→ 下游（ScriptGenNode）
```

### 2.3 工作流

```
组节点（28 个章节文字节点）
  ↓ 连线
循环遍历节点
  ├─ 当前推送：第 1 章内容
  ↓
ScriptGenNode（写一次提示词，复用）
  ↓
ImageNode × 5
```

操作流程：
1. 点「▶ 推送当前」→ 将当前章节文本注入下游 ScriptGenNode
2. 手动点 ScriptGenNode 生成分镜
3. 手动点分镜图生成图片
4. 点「下一个 ▶」→ 切换到第 2 章，重复

每章只需 3 次点击（推送 → 生成脚本 → 生成图），28 章 = 84 次点击，且画布保持干净。

### 2.4 节点数据结构

```ts
interface LoopNodeData {
  id: string
  type: 'libtv_loop'
  label: string
  category: 'process'
  position: { x: number; y: number }
  config: Record<string, unknown>
  // 配置
  sourceGroupId?: string      // 连接的组节点 ID
  filterType?: string         // 过滤节点类型，默认 'libtv_script'
  // 状态
  currentIndex: number        // 当前指向第几个
  cachedItems?: Array<{ id: string; label: string; content: string; charCount: number }>
}
```

### 2.5 推送逻辑

点「推送当前」时：
- 获取下游第一个 ScriptGenNode（或任意连接节点）
- 调用 `updateNode(downstreamId, { sourceText: currentChapter.content })`
- ScriptGenNode 检测到 `sourceText` 变化后，自动填充提示词面板的上游文本

## 功能三：组内自动排版

组内节点超过 6 个时，进入组内显示「自动排版」浮动按钮：

```ts
function autoLayout(nodes: NodeData[], edges: EdgeData[], mode: 'grid' | 'tree'): NodeData[] {
  if (mode === 'grid') {
    const COLS = Math.ceil(Math.sqrt(nodes.length))
    return nodes.map((n, i) => ({
      ...n,
      position: { x: (i % COLS) * 320, y: Math.floor(i / COLS) * 260 }
    }))
  }

  ...
}
```

## 开发顺序

```
Phase 1：组节点（libtv_group）
  Step 1-1: 数据结构 + 组节点组件（收起/展开 UI）
  Step 1-2: 组内画布（嵌套 ReactFlow 或层级导航）
  Step 1-3: 框选打组（右键菜单）
  Step 1-4: 组内自动排版

Phase 2：循环遍历节点（libtv_loop）
  Step 2-1: 节点组件 + 来源/类型选择
  Step 2-2: 读取组内节点列表
  Step 2-3: 推送当前内容到下游节点
  Step 2-4: 上一个/下一个翻页
```

Phase 1 难度较高（嵌套画布是技术难点），Phase 2 相对独立、难度中等。

---

## 技术难点

### 嵌套 ReactFlow

ReactFlow 官方不直接支持嵌套画布。两种实现方案：
- **方案 A（推荐）**：不嵌套，用「层级导航」——点进组时切换 projectStore 的 `currentNodes/currentEdges` 到组内数据，并记录导航栈。本质是「切换画布数据」而非「嵌套画布」。
- **方案 B**：使用 `parentNode` 属性实现 ReactFlow 原生 Sub-flow，节点在父节点内部渲染，但拖拽/缩放体验较差。

推荐方案 A，改动集中在 `projectStore` 加入导航栈逻辑。

### 循环节点推送

需要 ScriptGenNode 支持接收「外部注入文本」（`injectedText` prop），当 `injectedText` 变化时更新上游内容显示。这与 WorkflowRunner 的 `injectedInputs` 概念相同，可以先做最小版本。

## 与现有功能的关系

| 现有功能 | 关系 |
|---|---|
| ChapterSplitNode 批量创建章节节点 | 创建后直接「打组」收纳，画布整洁 |
| ScriptGenNode 分镜生成 | 循环节点推送文本给 ScriptGenNode，提示词复用 |
| ADD_WORKFLOW 拓扑布局 | 自动排版算法可复用 |
| projectStore 节点管理 | 组内画布导航需扩展导航栈 |
