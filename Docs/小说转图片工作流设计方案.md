# 小说转图片工作流设计方案

## 背景

用户有 Markdown 格式小说文件，希望通过节点工作流自动完成：
加载小说 → 分解章节 → 每章分解若干部分 → 每部分生成一张配图。

---

## 目标工作流

```
[小说文件 .md]
      ↓ 导入
[ScriptNode] 小说全文
      ↓ 章节分解节点
[ScriptNode 第一章] [ScriptNode 第二章] ... [ScriptNode 第N章]
      ↓ 每章接 ScriptGenNode
[ScriptGenNode] 分解为 5-10 个分镜段落（含画面描述）
      ↓ 「生成分镜」批量创建
[ImageNode×5~10]（每段一张配图）
```

---

## 工作项清单

### Task 1：ScriptNode 支持 MD / TXT 文件导入

**目标**：在 ScriptNode 的工具条或空状态区域加一个「导入文件」按钮，读取 `.md` / `.txt` 文件内容，填充到文本区（`content` 模式）。

**实现要点**：
- 在 idle / content 模式的工具条加「导入」图标按钮（`FileText` 图标）
- 点击触发隐藏 `<input type="file" accept=".md,.txt">` 
- `FileReader.readAsText` 读取内容，写入 `text` state 并 `updateNode`
- 文件名可自动设为节点 label
- 文件较大时截断提示（建议上限 50 万字符）

**涉及文件**：`frontend/src/components/nodes/ScriptNode.tsx`

---

### Task 2：新建章节分解节点（`libtv_chapter_split`）

**目标**：接收上游 ScriptNode 的全文，AI 按章节标题语义分割，用户勾选后批量创建 ScriptNode 章节节点。

#### 2.1 节点外观（content 模式）

```
┌─────────────────────────────────────┐
│ 📖 章节分解          [运行] [✕]      │  ← 标题栏
├─────────────────────────────────────┤
│ ● 第一章  爱恨缘起（1,200 字）  [✓] │
│ ● 第二章  相遇（980 字）         [✓] │
│ ● 第三章  误会（1,450 字）       [✓] │
│ ...                                  │
├─────────────────────────────────────┤
│ 已选 3/5    ⚡ 生成 3 个章节节点     │  ← 底部操作栏
└─────────────────────────────────────┘
```

#### 2.2 AI 分割逻辑

优先级：
1. **按标题行分割**：识别 `# 第X章`、`## Chapter X`、`第X章 标题` 等格式，无需调 AI
2. **AI 语义分割**：标题不规则时，调 AI 返回 JSON：
   ```json
   [
     { "title": "第一章 爱恨缘起", "content": "..." },
     { "title": "第二章 相遇",    "content": "..." }
   ]
   ```
   system prompt 指定只返回 JSON 数组，复用 `streamAI` + `systemOverride`

#### 2.3 生成章节节点

点击「⚡生成 N 个章节节点」：
- 每个选中章节创建一个 `libtv_script` 节点
- `label` = 章节标题，`content` = 章节正文，`initialMode` = `'content'`
- 节点布局：在当前节点右侧 +80，垂直居中排列，间距 320px
- 自动连线（`libtv_chapter_split` → 各章节 ScriptNode）

#### 2.4 节点数据结构

```ts
interface ChapterSplitNodeData {
  id: string
  type: 'libtv_chapter_split'
  label: string
  category: 'process'
  position: { x: number; y: number }
  config: Record<string, unknown>
  // 持久化
  chapters?: Array<{ title: string; content: string }>
  splitStatus?: 'idle' | 'splitting' | 'done' | 'error'
}
```

**涉及文件**：
- `frontend/src/components/nodes/ChapterSplitNode.tsx`（新建）
- `frontend/src/types/index.ts`（NodeData type 联合）
- `frontend/src/components/canvas/WorkflowCanvas.tsx`（nodeTypes 注册）
- `frontend/src/components/canvas/AddNodePanel.tsx`（菜单注册）
- `frontend/src/components/nodes/shared/NodeAddMenu.tsx`（+ 菜单）

### Task 3：AI 助手 Prompt 更新

在 `ai_assistant.py` 的 `ADD_WORKFLOW` few-shot 里补充「小说工作流」示例，让用户说「帮我搭一个小说转图片的工作流」时 AI 能自动搭出完整链路：

```
libtv_script → libtv_chapter_split → libtv_script_gen → libtv_image × N
```

**涉及文件**：`backend/app/api/v1/endpoints/ai_assistant.py`

---

## 开发顺序

```
Task 1（MD 导入）→ Task 2（章节分解节点）→ Task 3（AI Prompt）
```

Task 1 最小、独立，先完成验证导入链路；
Task 2 是核心，与已有「角色图提取」模式对称，可复用大量代码；
Task 3 收尾，让 AI 助手能一键搭建整条链路。

---

## 复用现有能力

| 现有能力 | 如何复用 |
|---|---|
| ScriptGenNode 章节→分镜表 | 每个章节节点接 ScriptGenNode，无需改动 |
| ScriptGenNode「生成分镜」→ ImageNode | 直接使用，无需改动 |
| streamAI + systemOverride | Task 2 的 AI 语义分割 |
| 角色图提取的 checkbox 面板 | 章节分解的选择面板 UI 完全对称，可参考复制 |
| ADD_WORKFLOW 扇出布局 | 章节节点批量创建时的布局逻辑 |

---

## 注意事项

- 小说文件可能很大（10 万字以上），AI 分割时只传章节标题行（先尝试正则），避免超出 token 限制
- 章节内容过长时，ScriptGenNode 生成分镜时也要截断处理（现有 ScriptGenNode 已有截断逻辑）
- `libtv_chapter_split` 节点的章节数据在 `updateNode` 中持久化到 SQLite，防止刷新丢失（参考 ScriptGenNode 的 `persistResult` 模式）
